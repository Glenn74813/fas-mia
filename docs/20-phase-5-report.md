# 20 — Phase 5 Report: Migration, Acceptance Support and Specification Gaps

Date: 2026-10-26. Plan: [15-phase-5-plan.md](15-phase-5-plan.md). Previous report:
[14-phase-4-report.md](14-phase-4-report.md). Specification review: [16-specification-compliance.md](16-specification-compliance.md).

Phase 5 had two parts. The first built the migration and acceptance tooling of the roadmap (slices 5a–5e). The
second closed all fourteen buildable gaps found when the repository was reviewed against the master specification
(§1–§29), the last being gap 14, movement-based statements. The variance analysis report from gap 2 is still open. Production cutover, UAT, the parallel run itself, the
penetration test and the production DR exercise are MIAA activities and have not happened.

Nothing has been committed to version control yet: by agreement, the repository is created once development
is done. The CI workflow therefore has never run.

## 2. Controls added in this phase and where they are enforced

| Control | Enforced by |
|---|---|
| Migration batches cannot post twice or unreconciled | `MigrationService` (SHA-256 and per-party reconciliation gate, second-person apply) |
| One inbox shows exactly what the module would let the user do | `ApprovalInboxService` reusing `DocumentWorkflow.canAct` |
| Retries do not duplicate money movements | `IdempotencyService` on receipts, payment instructions, allocations and postings |
| Secrets and personal data stay out of logs | `LogMasker` and the logback converters; `SensitiveLogIT` |
| Stored files are encrypted | `ContentCipher`, `StoredContentEncryptionJob` (V35) |
| Financial role grants and approval limits | `RoleGrantService`, `ApprovalLimitService` (V37) |
| Open items clear only in balanced groups, reversibly | `ClearingService` (advisory lock, unique active line index, V40) |
| Close tasks are ticked off only by their owners | `CloseCalendarService` (responsible permission per task) |
| Changes are released only with a rollback plan, staging validation by someone other than the assignee, and release notes | `TicketService` (V41) |
| Unreviewed static-analysis findings fail the build | SpotBugs/FindSecBugs in `mvn verify`, `spotbugs-exclude.xml` |

## 5. Not delivered / known limitations

* The variance analysis report (gap 2).
* Movement statements: no indirect-method cash flow; the SCE opening balance leaves out the result of an earlier
  fiscal year that was never closed (16 §3l).
* Everything listed in 16 §4 as blocked on MIAA decisions (C-00, C-04, C-06, C-07, C-08, C-10–C-13, C-15,
  C-16, C-21–C-25, C-27, C-28, C-30, C-31, C-32, and the new C-33 close calendar and C-34 ticket
  classification).
* Development uses budget enforcement WARN (no seeded budget); BLOCK is covered by `BudgetControlIT`.
* An unauthorised caller sending an invalid request body receives 400 with field messages rather than 403,
  because request validation runs before method security. Minor; noted in the threat model.
* Performance and DR results are from a workstation and are not acceptance evidence.
* External-auditor access expiry can be set only through the users API; the user screens show it but cannot
  set it.
* Only the audit tables are protected at the grant level; the other append-only tables rely on their triggers
  (docs/19 §9).
* No production environment, monitoring, immutable off-site backups or failover exist (C-04).
