# ADR-003 — Audit integrity
Status: Accepted. Decision: audit_events and security_events are insert-only, enforced by BEFORE UPDATE/DELETE/TRUNCATE triggers and by granting the runtime DB role only INSERT/SELECT (deploy/db/roles.sql). Each row stores SHA-256(prev_hash || canonical row); inserts are serialised per table with pg_advisory_xact_lock so the chain is linear. A verification endpoint recomputes the chain. Limitations (stated honestly): a database superuser can still disable triggers; tamper evidence, not tamper proof — monthly sealed exports to WORM object storage close that gap (Phase 2). Serialising inserts caps audit throughput (~thousands/s), far above target volumes; partition per year if volume requires.
